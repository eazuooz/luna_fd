# 루나 게임 로직 복구 기록

2026-11-08 기준. 실제 검증 결과는 `Logs/Revival`의 실행 보고서와 프로젝트 복구 보고서를 함께 확인한다.

## 런타임 데이터와 저장

- 원본 `Resources/ScriptableObjects`는 게임 설정 템플릿으로 유지한다. `LunaRuntimeData`가 플레이어, 유닛, 루나 스킨, 아이템, 스킬, 스테이지, 튜토리얼 데이터를 런타임 복제한다.
- 유닛·몬스터 `ObjectData`의 수치 원본은 `Resources/DataTables/UnitBalance.csv`다. 실제 Game Framework DataTable에서 읽어 SO 복제본에 적용한 뒤 개인 진행도를 복원한다. 이미지·프리팹·설명은 기존 SO에 남긴다. 편집 절차는 `UnitBalance-DataTable.md`에 기록했다.
- `LunaDataTable.Instance`는 플레이 중 별도의 테이블을 사용한다. `Status.objectData`는 직렬화된 원본 참조를 유지하면서 런타임 복제본을 반환하므로 프리팹과 기존 UI도 같은 진행 데이터를 읽는다.
- Game Framework `ISettingManager`에 `LunaSaveSettingsHelper`를 연결한다. 저장 대상은 `Application.persistentDataPath/Luna/LunaSave.dat`이다. 플레이어 진행 JSON, 소리 설정, 튜토리얼 순서를 같은 설정 저장소에 보관한다.
- 15초마다, 씬 변경 시, 앱 일시 정지 및 종료 시 저장한다. 전투 결과 확정과 소리 설정 변경도 즉시 저장한다. 강제 프로세스 종료 직전 변경은 마지막 저장 시점까지 복구된다.
- 임시 파일을 먼저 작성하고 원자적으로 교체하며 이전 파일은 `.bak`으로 보관한다. 바이너리 파일을 읽을 수 없을 때 백업을 시도한다. JSON 구조나 버전이 유효하지 않으면 자동 저장을 중지하여 기존 파일을 덮어쓰지 않는다.
- 공개 확인용 API: `LunaRuntimeData.Initialize()`, `SaveNow()`, `Reload()`, `IsInitialized`, `SaveDirectory`. 자동 테스트는 플레이 시작 전에 `LUNA_SAVE_DIRECTORY` 환경 변수를 별도 디렉터리로 지정한다. 실제 사용자 저장과 섞이지 않는다.
- 저장에는 Unity 인스턴스 ID나 에셋 참조를 넣지 않는다. 영웅/스킬/스테이지는 이름, 아이템은 번호로 복원하며 런타임 프리팹 참조는 다시 구성한다.
- 아직 기존 외부 서비스나 과거 출시판의 저장 형식에서 가져오는 마이그레이션은 없다. 기존 코드에는 게임 진행을 디스크에 저장하는 구현이 없었다.

## 수정한 게임 동작

- 로딩 화면은 중복 입력을 막고 실제 씬 로드 준비가 끝난 뒤 전환한다. `UILoading.ContinueToLobby()`를 사용자 입력과 자동 검증에서 공통으로 사용한다.
- UI 씬 전환은 새 프레임워크의 `LunaSceneManager.LoadScene`을 통한다.
- 플레이어 업그레이드는 최대 레벨을 먼저 검사한다. 실패한 업그레이드가 골드를 차감하던 문제, 부활 업그레이드의 상한 초과, 음수 비용을 수정했다.
- 덱/장착 스킬 개수와 리소스 경로, 저장된 스테이지와 스킨 번호를 검증한다. 로비 유닛 제거 시 배열 인덱스를 증가시키지 않던 문제를 수정했다.
- 루나 이동 속도 업그레이드 UI가 성공 후 갱신되지 않던 조건과 `NewLobby`라는 존재하지 않는 씬 이름을 수정했다.
- 소리 켜기/끄기는 `Luna.Sound.Enabled` 설정으로 저장하고 전역 볼륨에 적용한다. 나중에 생성되는 효과음에도 적용된다.
- 캐릭터 정보창의 스타스톤 이미지 경로와 소환 목록의 마지막 영웅(Tira)이 제외되던 난수 상한을 수정했다.
- Martin 소환 유닛의 누락 초상화는 실제 같은 캐릭터의 기존 `martin.png`에 재연결한다. UIReference 캐시는 현재 UI 프리팹의 실제 계층/오브젝트 ID로 재구성한다.
- 승리한 스테이지의 `isClear`가 기록되도록 했다. 스테이지 다음 번호와 마지막 스테이지 처리는 프레임워크 데이터 관리자에서 수정한다.
- 존재하는 21~30층 스테이지에 빠져 있던 `Stage03-01`~`Stage03-10` 진행 기록 에셋을 기본 미완료 상태로 추가했다. 테이블은 폴더의 모든 StageData를 로드한다.
- 플레이어 빌드를 막는 런타임 UI 파일의 `UnityEditor` 의존을 제거했다.
- Entity 재사용 시 영웅 등급 효과는 Status 초기화 후 적용한다. Ria/Lena의 Spine 공격 이벤트 중복 구독을 제거하고, 소환수 첫 생성 직후의 강화가 초기화로 사라지지 않도록 했다.
- Dwarf 소환수의 재사용 시 체력·스킬 상태를 초기화한다. Status의 전용 AudioSource도 재사용하고, 숨김 시 재생을 중단하여 재소환마다 컴포넌트가 늘어나지 않게 했다.
- Status가 붙은 캐릭터 UI 미리보기는 Entity로 생성하고 폼을 닫을 때 정리한다. 일반 UI 이미지·스킨 미리보기는 기존 UI 객체로 유지한다.

## 채팅은 선택 기능

`ChatManager.connectOnStart`는 기본적으로 꺼져 있다. 별도 호환 서버를 운영할 때 주소/포트를 설정하고 연결한다. 개발용 기본 주소는 기존과 같은 `127.0.0.1:7979`이며 공용 서비스로 간주하지 않는다.

연결이 없으면 전송 버튼을 비활성화하고 직접 호출도 안전하게 무시한다. 소켓 콜백은 스레드 안전 큐에 문자열만 넣고 Unity 객체 접근은 메인 스레드에서 수행한다. 종료 시 소켓을 닫고, 대기 중 뒤늦게 연결되어도 종료된 세션으로 넘기지 않는다. 채팅 기록과 패킷 크기에 제한을 둔다. 서버 프로토콜, 재접속, 인증, 운영 보안은 이번 복구에서 새로 설계하지 않았다.

## 남아 있는 프로토타입 기획

아래는 코드가 돌아가는 문제와 별개인 기존 게임 규칙이다. 임의의 밸런스나 결제 정책을 만들지 않았다.

- 기본 PlayerData 에셋에 약 120만 골드/스타스톤이 들어 있고, 유닛 기본 카드 수는 99이다.
- 영웅 소환은 재화를 차감하지 않는다. 스타스톤 구매 버튼도 결제 검증 없이 재화를 지급하는 개발용 동작이다.
- 스킬 레벨업에 가격과 최대 레벨 규칙이 없다.
- 드롭률, 성장 곡선, 전투 밸런스, 튜토리얼 완성도, 장비/영웅 조합 전체는 플레이 테스트와 기획 결정이 필요하다.
- 실제 스토어 결제, 광고, 계정 서버, 클라우드 저장, Android 기기 입력과 성능은 별도 통합 및 검증 대상이다.
- 원본 파일이 없는 미사용 Grassfield/Tree/Adventure 프로토타입은 `Legacy/UnresolvedAssets`에 원본 메타와 함께 보관한다. 누락 GUID와 정리 근거는 그 폴더의 README에 기록했다. 원본 아트 복구가 끝났다는 뜻은 아니다.

따라서 이 복구는 배포 가능한 상용 경제 시스템이 완성되었다는 의미가 아니다. 현재 구현과 실행 검증의 범위는 실행 보고서를 기준으로 판단한다.
