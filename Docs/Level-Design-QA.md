# 루나 디펜스 레벨 디자인과 검수

## 2026-11-15 제한시간과 개발자 모드

사용자가 확인한 2스테이지 패배는 적 거점 파괴 뒤 승패가 뒤집힌 문제가 아니라 제한시간 초과였다. 기존 72 게임 초는 기본 1.5배 속도에서 실제 약 48초였다. 2층은 **120 게임 초(실제 약 80초)**로 늘렸다. 1–10층은 각각 105·120·120·120·130·120·125·130·135·145초이며, 11–30층은 기존 값에 30초를 더했다. 적 체력·공격력·웨이브·보상과 승패 판정 순서는 유지한다.

개발자 모드는 Editor 또는 Development Build에서만 쓸 수 있고 처음에는 모든 기능이 꺼져 있다. GameFramework의 Procedure가 키 입력을 처리하고, 기본 Debugger에 `Luna` 창을 등록한다. 메뉴가 열린 동안 뒤 UI와 로비 캐릭터의 클릭을 막는다.

| 키 | 기능 |
| --- | --- |
| F1 | 개발자 메뉴 열기/닫기. 메뉴만 열면 일반 진행은 그대로 저장된다. |
| F2 | 아군 체력 무한 켜기/끄기. 루나·동료·아군 거점을 보호한다. |

첫 기능 적용 전에 정상 진행을 저장하고 스냅샷을 보관한다. 테스트 중 자동 저장·뽑기·강화·결과 정산은 정상 스냅샷을 저장한다. 따라서 개발자 모드에서 번 재화·보상·클리어·뽑기 결과는 일반 진행에 남지 않는다. 기능을 개별적으로 꺼도 테스트 세션은 유지되며, F10으로 종료하거나 게임을 재실행하면 원래 진행으로 돌아간다. 메뉴를 닫아도 켜 둔 기능은 유지되고 화면에 개발자 모드 표시가 남는다.

검수 체크리스트는 초반 조작 지연을 포함한 실제 전투, 기본 10개 층의 일반 플레이, 체력 무한의 켜기/끄기와 적 피해, 실제 뽑기와 저장 원문 비교, 3종 던전의 무제한 시간·클리어, F10 복원, 개발자 기능을 켠 채 종료한 뒤 다른 실행 프로세스에서 원래 진행과 기본 OFF 복원, UI 회귀와 자원 정리다. 단축키·버튼이 공통으로 호출하는 명령을 자동 실행하며 물리 키보드 조작이나 Debugger IMGUI 창의 픽셀 검증으로 확대하지 않는다.

밸런스·기능 검사 시점의 소스 지문은 `c2d07d4fba3903542705c38be49bf1cd990c9234f29b179eef0be96573345a9e`이며 검수 전후 같았다. `time-dev-stage2-delay45-seed421/909/1907`은 처음 45 게임 초(실제 약 30초) 동안 조작 결정을 지연하고 이후 일반 소환·이동·스킬을 사용했다. 세 실행 모두 72.76·74.07·73.92 게임 초에 승리했다. 기존 72초 제한을 넘긴 시점의 승리를 실제 전투로 확인했으며, 기존 제한의 패배를 별도 실행했다고 표시하지 않는다.

`time-dev-final-chapter1-casual`은 기본 1–10층에서 무적·무한 재화 없이 모두 승리했다. 권장 레벨과 기본 편성을 사용하는 자동 플레이이며 사람이 느끼는 재미의 검증으로 해석하지 않는다. `time-dev-contracts-v3`의 기능 검사 18개는 보스·무한던전까지 개발자 기능과 원상복구를 확인했다. UI 29개(`time-dev-final-ui`), 구성 15개, 기본 실행 8개도 통과했다. 기본 실행의 경고 4개는 저장 손상·잠금 복구 검사에서 예상한 내용과 일치했다.

Windows 검사 `time-dev-final-panels`는 41개를 통과했다. `time-dev-final-player`의 seed 4개·verify 10개는 개발자 기능을 켠 채 실제 프로세스를 종료한 뒤 다른 프로세스에서 원래 재화·카드·진행과 기본 OFF 복원을 확인했다. 122.74초 동안 전투·로비를 5회 순환했고, `time-dev-final-early`의 조기 종료 1개도 통과했다. Windows 검사 오류·경고는 모두 0개다.

마지막에는 `LunaNativeValidation.DeveloperMode.cs`에 개발자 상태의 UGUI 캡처 검사만 더했다. 게임 실행 로직·에셋·밸런스는 같다. 이 최종 소스의 전후 지문은 `3e5e805b6b17382805f49988ceb4430adcb8ec2645582690f0a9a6eaee494ea9`로 동일하다. 새 빌드 오류·경고 0개와 `time-dev-final-presentations`의 Windows 41개가 다시 통과했다. 1280×720·1920×1080·1024×768에서 개발자 표시·지갑 ∞·전투 시간 무제한의 화면 6개를 저장하고 확인했다. 기본 Debugger IMGUI 메뉴 자체의 픽셀을 검증했다고 주장하지 않는다.

종료 로그의 명시적 native 메모리 오류는 0개이며 귀속 미확인 UTP 집계는 원본에 보존했다. 이미 실행 중인 기존 게임을 덮어쓰지 않도록 최종 실행 파일은 **`Builds/Revival/Windows-20261115-dev/LunaDefense.exe`**에 별도로 만들었다.

## 2026-11-14 UI·카메라·사운드 복구

사용자가 제공한 실제 실행 이미지에서 이전 검수가 놓친 화면 문제를 확인했다. 화면 안에 사각형이 들어오는 검사만으로 팝업의 표시 순서나 내부 마스크 잘림까지 검증할 수 없었다. 아래 변경은 기존 그림과 프리팹을 사용하며 캠페인 30층과 공개 던전 5개의 구성·해금 조건을 유지한다.

- **카드 뽑기:** 결과 폼이 상점보다 낮은 Main 그룹에 있었고, 아바타의 별도 Canvas가 위로 튀어나왔다. 결과를 Popup 그룹에 넣고 뒤 상점을 일시적으로 가리며 자식 Canvas는 폼의 순서를 상속한다. 실제 구매로 5·1·10장 결과를 열고 닫아 상점 복원과 한 번 차감을 검사한다. 두 줄 결과는 마스크 안쪽 여백을 포함해 크기를 계산한다.
- **맵:** 왼쪽 목록의 앵커와 자동 폭 계산을 수정했다. 상세 정보의 전체 화면 이미지를 없애고 오른쪽에 제목·보상·공략·몬스터·아이템·입장 버튼을 배치했다. 몬스터와 아이템은 80 크기로 맞춰 세로 잘림을 없애며 길면 가로로 넘긴다.
- **던전:** 비활성 상태로 남아 있던 RedDragon·SixHeroes 원본 그림 카드를 복구했다. 공개 던전 5개의 이름·이미지·설명·권장 레벨·보상·해금 조건을 표시하고 가로로 넘긴다. 원본 버튼의 고정 던전 번호 대신 해당 데이터 행의 정보와 입장 경로를 연결했다.
- **카메라:** 첫 전투 시작 시 빠져 있던 추적 활성화를 추가했다. 화면 흔들림이 추적을 끊지 않는다. UI 위의 클릭은 카메라 드래그를 시작하지 않으며, 배경 드래그를 놓으면 다시 루나를 따라간다.
- **사운드:** 로비에는 음악 재생 요청 자체가 없었다. 기존 음악을 `Luna/Audio/Lobby`로 등록해 GameFramework Sound에서 재생하고 로비 종료 시 해당 재생 번호를 정리한다. 저장한 음소거는 부팅 때 적용한다. 로비·전투의 실제 음악 신호와 음소거·복원을 별도로 측정한다.

최종 체크리스트:

1. 프로젝트 구성, 로비→전투→복귀, 기존 저장의 보존과 오류 시 복구.
2. 맵 좌우 영역 분리, 몬스터·아이템 마스크 내부의 세로 표시, 던전 첫 페이지와 마지막 페이지의 그림·설명.
3. 첫 무료 5장과 유료 1·10장 구매, 결과 표시 순서, 모든 결과 카드의 마스크 내부 표시, 닫은 뒤 상점 복원.
4. 실제 루나 이동과 첫 전투 카메라 추적, 소환·화면 흔들림 뒤 추적 유지.
5. 로비와 전투의 실제 음악 PCM 출력, 음소거 0과 복원, 별도 프로세스의 설정 복원.
6. Windows 실행에서 1280×720·1920×1080·1024×768 렌더 이미지 확인, 반복 씬 전환, 종료 후 소유 자원 정리.

전체 기능 검사는 `Logs/LevelDesign/ui-repair-final-all`에서 **458개 통과, 오류 0개**다. 경고 1개는 `LUNA_INJECTED_OWNERSHIP`의 없는 자원을 일부러 요청하는 복구 검사와 정확히 일치했다. 이 실행의 작성 소스 지문은 `4feb00f667967445110f66f95e1000fd39f2dec3112364775096c54cf1389cff`다.

Windows 최종 화면 검사는 `Logs/Revival/PlayerValidation/ui-repair-panels-v3`에서 **40개 통과, 오류·경고 0개**다. 실제 맵 선택과 5·1·10장 구매로 3개 해상도의 화면 15개를 저장했고, 상점·던전 마지막 페이지·보스 정보·전투 안내·패배·보스 경고 이미지도 확인했다. 아이콘은 바깥 행뿐 아니라 내부 이미지까지 마스크 안에 들어오는지 검사한다. 중간 v1·v2 이미지는 마지막 보정 전의 근거로만 남긴다.

로비 음악의 첫 Windows 검사는 설정 UI가 비동기로 뜨기 전에 버튼을 찾는 검사 순서 문제로 실패했다(`ui-repair-audio-v2`). 최종 검사는 설정 UI가 준비될 때까지 기다린다. 전체 검사 이후 변경된 작성 파일은 이 대기 한 줄이 들어간 `LunaNativeValidation.Player.cs` 하나이며, 게임 실행 로직과 에셋은 같다. 최종 작성 소스 22,378개의 지문은 `f650774333e6a737722843b4eb2e420572e67068bbb800016fb2aaea285b8175`다. 최종 Windows 빌드는 오류·경고 0개로 완료했다.

대기 조건 변경 이후에도 구성 15개, 기본 실행 8개, UI 29개(`ui-repair-final-v4-ui`), 이번 복구 계약 17개(`ui-repair-final-v4-contracts`)가 다시 통과했다. 오류는 0개이며 기본 실행의 경고 4개는 격리 저장을 일부러 손상·잠금 처리하는 기존 복구 검사와 정확히 일치했다.

최종 Windows 음악 검사에서 실제 로비 RMS는 `0.0249393284`, 실제 전투 RMS는 `0.0108869076`이었다. 두 값 모두 검사 음원을 섞기 전에 측정했다. 별도의 음소거 검사는 48,000Hz에서 혼합 출력 `0.0139728729` → 음소거 `0` → 복원 `0.0135095725`를 확인했다.

최종 Windows 실행 기록은 `Logs/Revival/PlayerValidation/ui-repair-final-player`의 seed 3개·verify 10개와 `ui-repair-final-early`의 조기 종료 1개다. 모두 오류·경고 0개다. 서로 다른 실행 프로세스의 저장·음소거 복원을 확인했고, 302.93초 동안 전투와 로비를 11회 순환했다. 각 로비의 살아 있는 객체와 EntityData 사용 수가 일치했으며, 종료 뒤 게임 소유 자원·요청·캐시 수는 0이었다. 메모리 표본은 장시간 무누수의 증명으로 해석하지 않는다. 종료 로그의 명시적 native 메모리 오류는 모두 0개이며 귀속 미확인 UTP 집계는 그대로 남긴다.

검수 후 작성 소스 지문은 최종 빌드 전과 같은 `f650774333e6a737722843b4eb2e420572e67068bbb800016fb2aaea285b8175`다. Windows 실행 파일은 `Builds/Revival/Windows/LunaDefense.exe`이며 최종 빌드 파일 지문은 `Logs/UIRepair/artifacts-final.json`에 기록했다.

검사는 격리 저장과 숨겨진 Unity/Windows 실행으로 진행한다. 생성한 이미지를 직접 확인하며 물리 화면·키보드 조작, 스피커 청취, 모바일 기기 검증을 수행했다고 표현하지 않는다. 엔진 UTP 종료 집계는 기존과 같이 원본에 보존하며 프로젝트 소유 객체의 해제 결과와 구분한다.

기본 스테이지는 30층이다. 앞 층을 클리어하면 다음 층이 열린다. 이미 열린 층은 재도전할 수 있고, 30층을 클리어하면 완료 기록을 저장한다. 편성과 안내는 [Stages.csv](../Assets/Resources/DataTables/Stages.csv), 증원 시간표는 [StageWaves.csv](../Assets/Resources/DataTables/StageWaves.csv)에서 편집한다.

- 붉은 용, 루가니, 늑대왕 보스전은 각각 기본 5·15·25층 뒤 열린다. 기존 보스 능력에 체력 65%와 30%의 증원을 더했다. 루가니의 폭풍은 동료가 있던 자리를 표시하고, 그 위치에 남은 대상에게 기절을 건다.
- 무한던전 **여섯 영웅**은 10층 뒤 열린다. 선택한 여섯 동료를 처음에 배치하고 생존한 동료를 다음 층에 데려간다.
- 무한던전 **잿빛 행군**은 20층 뒤 열린다. 전투 골드로 동료를 다시 배치하며 모글과 마틴의 합동 공격을 상대한다. 층을 넘으면 전투 골드와 마나가 보급된다. 정예층에서는 마틴이 앞을 막고 궁수와 포격수가 뒤를 받친다.
- 무한던전은 5가지 편성을 돌리고 5층마다 정예를 배치한다. 층이 오를 때 적의 체력과 공격 배율이 오르고, 클리어 뒤 생존 아군은 일반 층에서 최대 체력의 12%, 정예 층에서 28%를 회복한다. 완료한 층의 골드와 정예 보상은 결과 또는 퇴장 시 한 번 정산한다. 최고 층과 새 기록의 별석 보상도 저장한다.

## 골드, 카드, 강화

새 저장은 700골드, 별석 0, 기본 등급에서 시작한다. 캠페인 첫 승리는 737–2,010골드이며 5층마다 별석과 강화 재료를 준다. 재도전은 층에 따라 192–540골드다. 보스 첫 승리, 무한던전 완료 층도 별도 보상을 준다. 라운드에서 동료를 부르는 전투 골드는 영구 골드와 별개다.

상점의 첫 5장은 한 번 무료다. 이후 1장 420골드, 10장 3,800골드를 차감한다. 일반 추첨의 영웅 확률은 35%이며, 뽑힌 종류의 카드가 덱에 있으면 70% 확률로 그 종류의 덱 카드에서 뽑는다. 10장 소환은 영웅 한 장을 보장한다. 승급에 필요한 카드는 2·3·4·5·7·9장이다. 두 각성은 각각 별석 2·4개도 사용한다. 승급마다 전투 배치 체력과 공격력이 5% 오른다. 골드로 올리는 레벨 비용은 700골드부터 오르며 루나와 유닛은 레벨 20까지 성장한다.

이미 플레이한 저장은 유지한다. 이전 버전의 테스트 별석 잔액 패턴이 확인될 때만 프로토타입 지급분을 변환한다. 이 경우 기존 레벨, 덱, 아이템, 저장된 스테이지를 유지하고 확인할 수 있는 초과 골드와 카드 수를 남긴다. 변환 뒤 저장은 v2를 사용한다.

## 전투 피드백과 초반 학습 개선

2026-11-14의 변경은 현재 전투와 성장 구조 안에서 다음 다섯 항목을 개선한다.

- 판이 끝나는 순간 시간 초과, 아군 거점 파괴, 루나 사망을 구분해 기록한다. 기본·보스전 패배 화면에는 그 시점의 적 거점 또는 보스 체력 비율을 표시한다.
- 소환 카드는 합류 중, 재사용 대기, 골드 부족, 출전 중을 구분한다. 대기시간은 실제 소환 쿨다운의 진행 속도로 환산하고, 출전 영웅의 체력 비율도 표시한다. 스킬 충전 게이지는 유지한다.
- 붉은 용의 불꽃과 폭격, 벨레린의 출혈 파동, 루가니의 낙뢰는 타격 위치와 남은 시간을 HUD에 표시한다. 예고 위치는 타격 전에 고정된다. 붉은 용은 1.1초 뒤 반경 1의 영역을 공격하고, 벗어난 대상은 맞지 않는다. 붉은 용과 벨레린은 기술 뒤 0.8초 동안 다음 일반 행동을 늦춘다. 죽거나 전투에서 퇴장한 시전자의 대기 공격은 종료한다.
