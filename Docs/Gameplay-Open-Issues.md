# 원본 설명과 게임 구현의 남은 차이

`UICharacterInfo.UpdateWakeUpInfo()`는 각 `Resources/ScriptableObjects/Heroes/*.asset`의 `start3`, `start5`, `ultra1`, `ultra2`를 그대로 보여 준다. 아래는 해당 설명과 실제 코드를 대조한 결과다. 테스트 통과와 별개로 기획·구현이 일치하지 않는 항목을 숨기지 않기 위한 기록이며, 모호한 효과를 임의로 추가하지 않았다.

이 목록에는 **이미 확인된 구현 누락·수치 불일치**와 **규칙을 추가로 정해야 하는 항목**이 함께 있다. 모든 항목을 단순한 기획 취향으로 분류하지 않는다. 예를 들어 Mei의 승급 보너스 덮어쓰기와 소환 지속 시간 부재는 확인된 동작 문제이며, 어떤 값·종료 처리를 채택할지는 원본 설명과 현재 코드의 충돌까지 검토해야 한다. 이번 복구의 실행·수명·저장 검증 통과가 아래 효과까지 완성됐다는 뜻은 아니다.

| --- | --- | --- |
| `Miu.asset.start5` | 자신이 사용하는 '엄마 손' 저주 10감소 | `Miu.Skill()`은 회복만 수행한다. `Status.Curse()`는 방어력·이동 속도를 각각 0.8배로 낮추지만 저주 누적값·기간·제거 API가 없다. '10'의 단위와 복원 규칙을 정해야 한다. |
| `Matilda.asset.ultra1` | 자신이 소환하는 미니 마틴 / 마틴 (불) 무적 | 실제 `Mni_Martin`, `MartinBall` 프리팹에는 Status와 Unit 태그가 없다. 전 등급에서 공격받는 유닛이 아닌 이동 공격 효과다. 주석의 `GetComponent<Status>().Invincible(0)`을 단순 복원하면 null 예외가 발생한다. 등급별 피격 가능 유닛으로 바꿀지, 설명을 현재 방식에 맞출지 결정이 필요하다. |
| `Ria.asset.ultra2` | 해골의 왕 벨레린 60초동안 1회 소환 (쿨타임 33초) | ULT2 해금 조건은 복구했지만 `Ria.UltSkill()`과 실제 `SkeletonKing` 프리팹의 `UnitAI`·`Bellerin`에는 60초 종료 타이머가 없다. 소환수가 살아 있는 동안 다음 궁극 소환을 보류하며 사망·씬 종료로 제거한다. 60초 지속은 구현되지 않은 상태다. |

| `Mei.asset.start3`, `start5` | 스킬공격력 5% 증가 / 스킬 공격력 300% 증가 | STAR3의 옛 스킬 계수 적용은 주석 상태다. STAR5에서 더한 피해도 `OnEntityUpdate()`가 매 프레임 `AttackDamage * 5`로 덮어쓴다. 보너스 소실은 확인됐지만, 원본의 '300% 증가'와 코드의 `5+8` 배율이 다르므로 최종 산식을 확정해야 한다. |
| `Mei.asset.ultra1` | 스턴 저항 20% 증가 | 옛 `stunResist` 대입이 주석 상태이고 현재 Stat에는 스턴 전용 저항이 없다. 회피 확률인지 지속 시간 감소인지 정하지 않고 일반 디버프 회피로 대체하지 않는다. |
| `Scarlet.asset.start3`, `start5` | 스킬 공격력 5% 증가 / 스킬 데미지 200% 증가 | `Scalet.STAR3()`은 `coefSkill_1`을 1에서 2로 바꿔 기본 대비 2배가 되고, STAR5는 `coefSkill_2`를 8에서 10으로 바꿔 STAR3 대비 1.25배가 된다. 실제 피해는 `AttackDamage * 5 * coefSkill_1 * coefSkill_2`다. 설명의 5%·200%와 수치가 일치하지 않으며, 기존 수치를 임의로 재설계하지 않았다. |
| `Scarlet.asset.ultra1` | 스킬 피해 데미지 감소 20% 감소 | 옛 `SkillResistance += 0.2f`는 주석이다. ObjectData/CSV의 SkillResistance 수치는 존재하지만 현재 `Status.Attack()`에는 이를 사용하는 피해 계산이 없다. 피해 감소의 대상·중첩 규칙이 필요하다. ULT2의 80% 저주 호출은 별도로 복구했다. |
| `Dren.asset.start3` | 공격 데미지 15% 증가 | STAR3은 현재 타깃이 있을 때 +30%를 적용하는 조건을 활성화한다. 원본 설명과 수치·발동 조건이 모두 다르다. |
| `Dren.asset.ultra1` | 전체 파티원 공격 받는 데미지 10% 감소 | ULT1에는 주석만 있고 일반 파티 피해 감소 구현이 없다. 기존의 보스 전용 피해 보정과 같은 것으로 처리하지 않는다. |

| `Rose.asset.ultra2` | 적군 공중 전체 공격력 10% 감소 | 공중 분류가 없어 현재는 모든 적군에 적용한다. 대상 분류를 새로 정해야 한다. 활성화/해제 시 같은 적군의 계수를 대칭 복원하는 오류는 수정했지만 공중 대상 제한은 구현되지 않았다. |

| `Rose.asset.skillStr` | 아군 근거리 전체 … / 사정거리 5이내의 적군 전체 … | 대상 검색의 공통 필터 `IsSoldier`는 이름과 달리 `hitPriority == NORMAL` 조건이며 근거리 판별이 아니다. 따라서 근거리 아군만 선택하지 않고, 일반 우선순위가 아닌 적은 제외한다. 기존 `IsMelee` 판별은 존재하지만 원본 설명과 현재 적용 대상을 함께 정리해야 한다. 확률 80%/50% 복구와는 분리한 문제다. |

`Tira`, `Pobi`, `Lennon` 원본 에셋의 승급 설명은 비어 있다. 특히 Pobi/Lennon ULT2의 주석은 “속도 30감소?” 수준이라 확정된 규칙으로 볼 수 없다. Lennon은 스킬에서 3/4 소환 수를 계산하지만 실제 루프는 1회다. 이 코드상 불일치 역시 원본 화면 설명만으로 어느 값이 의도인지 확인할 수 없다.

위 항목들은 해결 완료 목록이 아니다. 기술적 실행 안정성의 복구와 별도로 남아 있는 콘텐츠 정확성 문제다. 명확한 원본 설명과 이미 구현된 API로 고칠 수 있는 장비 슬롯 번호, Lene 본인 확률, Ria/Lena 궁극 소환 해금, Scarlet 80% 저주는 복구 범위에 포함했다. 나머지 기획 차이는 원본 문구나 동작을 조용히 지우지 않고 위와 같이 남긴다.

추가로 Joe의 공격 애니메이션 콜백이 재소환 때 누적되던 수명 문제를 해제 가능한 단일 핸들러로 바꾸었다. 원래의 15%·2초 스턴 수치는 유지한다. Rose의 임시 100% 발동은 원본 주석과 설명의 아군 80%·적군 50%로 복구했고, 전역 효과 해제 시 같은 적군의 공격 계수와 계산된 공격력을 복원한다. 공중·대상 분류의 미해결 사항은 이 수정으로 해결된 것으로 표시하지 않는다.

검증 범위: 행위자 검사는 새 생성·풀 재사용·유한한 스탯과 짧은 스킬 발동을 확인한다. 특정 승급 경계 회귀 검사 외에는 모든 승급 수치, 장시간 소환 지속 시간, 모든 파티 조합의 효과 중첩을 증명하지 않는다. 실제 플레이어 스킬 14개와 영웅 고유 스킬·승급 효과는 별도의 범위이므로, 전자의 통과를 후자의 완성으로 해석하지 않는다.

별도 재사용 오류도 실제 진단으로 확인했다. `matrix-joe-prefixed-11.json`에서 ULT1 조를 풀에 넣은 뒤 STAR1로 꺼내면 공격 계수가 1.3이고, 다음 재사용에는 1.0이었다. 두 시점 모두 등급은 STAR1이고 승급 플래그도 이미 꺼져 있었다. 원인은 `ReadyUlt()`가 한 프레임 대기하는 동안 이전 등급 플래그로 파생 스킬 업데이트가 먼저 실행되어 +0.3이 남는 순서 문제였다. `LunaEntityBehaviour.CanEntityUpdate`와 `HeroSkillControl.rankReady`를 연결해 새 스탯·등급 초기화가 끝난 뒤에만 전체 영웅 스킬 업데이트를 허용했다. 초기화 대기와 기존 전투 수치는 유지했으며, 변경 후 통과 여부는 같은 교차 등급 재사용 검증의 실행 보고서로 판정한다.
